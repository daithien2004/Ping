# ADR-0012: Core data model

Status: accepted
Date: 2026-10-19 (records decisions made on 2026-10-18)

## Decision

- Ids are UUIDv7 generated by Prisma Client, stored as Postgres `uuid` (ADR-0005). Their time
  ordering makes `id` the pagination cursor: `WHERE channelId = ? AND id < ? ORDER BY id DESC`,
  backed by the index `(channelId, id DESC)`. No offset pagination.
- Messages are soft-deleted (`deletedAt`) so moderation keeps history and realtime clients can be
  told a message was removed. Listings filter out deleted messages; deleted messages cannot be
  edited.
- `Message (channelId, authorId, nonce)` is unique so client retries never create duplicates.
- Deletion rules: deleting a user cascades to sessions and memberships but is blocked
  (`RESTRICT`) while they own a server or have authored messages; deleting a server cascades to
  roles, members and channels; deleting a channel cascades to its messages.
- Role permissions are a 64-bit bitmask (`BigInt`), serialized to clients as decimal strings and
  accepted back as strings.
- Members carry the `@everyone` role row; its permissions are always counted (ADR-0004).

## Reason

Chat history is read newest-first in pages; keyset pagination stays fast at any depth. Message
history must not vanish when a moderator or a user account is removed.

## Alternatives considered

- Hard delete for messages — rejected: loses moderation history and realtime cannot reference it.
- Cascade user deletion to messages — rejected: one account removal would rewrite every channel's
  history. Account deletion will anonymize the user instead (not built yet).
- Numeric JSON for permissions — rejected: bitmasks can exceed `Number.MAX_SAFE_INTEGER`.

## Consequences

An account-deletion feature must transfer server ownership and anonymize the user rather than
delete the row.
