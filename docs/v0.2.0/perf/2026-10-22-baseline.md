## Profile và cách chạy lại

Chuẩn bị theo [runbook](../../perf/README.md): build, bật Postgres/Redis local, xác nhận DB
loopback rồi `pnpm --filter api loadtest:seed`. Seed chỉ dọn fixture trong DB `ping_load`;
không chạy vào môi trường khác. Các cổng bài đo phải đang rảnh.

```bash
node tools/loadtest/run-instances.mjs 3
node tools/loadtest/sample-metrics.mjs t0.6-2026-10-22 9101,9102,9103 3
k6 run --quiet --no-color --summary-export docs/v0.2.0/evidence/T0.6/rest.json tools/loadtest/rest-history.js -e PORTS=4001,4002,4003 -e RATE=20 -e DURATION=40s
k6 run --quiet --no-color --summary-export docs/v0.2.0/evidence/T0.6/fanout.json tools/loadtest/socket-fanout.js -e PORTS=4001,4002,4003 -e LISTENERS=500 -e SEND_RATE=20 -e SENDERS=500 -e DURATION=60s
k6 run --quiet --no-color --summary-export docs/v0.2.0/evidence/T0.6/reconnect.json tools/loadtest/reconnect-storm.js -e PORTS=4001,4002,4003 -e SOCKETS=500 -e ROUNDS=3 -e HOLD_S=15
```

REST RATE là **vòng/giây**, mỗi vòng 5–6 request, không phải request/giây. Script có warm-up
10 giây và đo chính 40 giây. Fan-out giữ listener 90 giây gồm 20 giây chờ trước gửi và 10 giây
chờ cuối. Reconnect không có backoff, 3 vòng đóng/nối, giữ 15 giây mỗi vòng.

Ngưỡng gốc của script giữ nguyên: REST p95 < 200 ms/lỗi < 0,1%; send p95 < 200 ms; fan-out
p95 < 500 ms; reconnect p95 < 5 giây và failure < 1% của 500 socket. Phạm vi ADR-0038 dùng
REST < 300 ms, lỗi < 1%, reconnect < 15 giây. Báo cáo sẽ phân biệt hai bộ ngưỡng, không sửa script.

### Kết luận và điểm cần theo dõi

- Tại profile pilot (500 socket đồng thời, 20 vòng/giây REST) tất cả ngưỡng script và ADR-0038 đều đạt,
  không có lỗi 5xx/socket failure; baseline này dùng để so sánh trước/sau khi sửa pool/presence.
- Hai điểm cần theo dõi khi tăng tải: (1) độ trễ kết nối socket p95 ~1,2–1,4 s và reconnect p95 3,14 s
  (gần ngưỡng script 5 s); (2) event loop p99 tăng lên 778,6 ms trong giai đoạn reconnect storm.
- RSS ~1,3 GB cho 3 instance/500 socket; chưa đo 10.000 socket hay chạy dài; không có proxy/TLS.
- Không có thay đổi code app trong baseline này; kết quả là mẫu local một lần, cần lặp lại và so sánh
  cùng profile trước khi kết luận về capacity production.

## Giới hạn

Một mẫu local; k6, API và Docker tranh CPU/RAM trên cùng host. Không có proxy/TLS hoặc máy
phát tải tách biệt. Không lặp lại profile lịch sử 2.000–4.000 socket; không suy giảm event so
với báo cáo 2026-10-20 từ hai mức tải khác nhau. Baseline này để đo trước/sau cùng profile pilot
khi sửa pool/presence. Chưa đo 10.000 socket, chạy dài nhiều giờ hoặc chi phí hạ tầng thật.
